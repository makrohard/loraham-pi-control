## Method, per finding
1. Open the file at the line; read the whole function and its callers (grep). Read the test that covers it, if any.
2. Reproduce when it is cheap and needs no hardware or root: a scratch script against `FakeSystem`
   (`tests/` shows how) or `python -m pytest -q -p no:cacheprovider <test file>` (if pytest is missing,
   `pip install pytest` first). Delete scratch files before the commit.
3. Verdict: CONFIRMED (the code does what the finding says, on the path the finding names), REFUTED (say which
   sentence is wrong and cite file:line), PARTLY (what holds, what not), or UNCLEAR (what you could not establish).
4. Severity check: keep the reviewer's severity or correct it (S1 = safety or data loss, S2 = wrong behaviour the
   operator meets, S3 = robustness under an unusual condition, nit = quality only) with one reason.
5. Fix size: one of trivial (≤ 10 lines, one file), small (one function or one file), medium (two or more files or a
   new test fixture), large (a design change). Risk of the fix: low / medium / high (can the fix break a working path?).
