# Stack: Voice

Codec2 voice over LoRa through the daemon, on 433 or 868 MHz, in two builds of one source: a GTK
desktop app (`loraham-voice`, needs a display and an audio device) and an ncurses terminal variant
(`loraham-voice-cli`) for headless/Lite boxes. The daemon runs **DIRECT** for voice: the app paces
its own TX by LoRa airtime, and a MANAGED CAD wait would gap live audio.

| | |
|---|---|
| Components | `loraham-voice` (main, `gui_optional`) · `loraham-voice-cli` (interactive terminal variant) |
| Source / pin | `src/LoRaHAM_Voice` ← `makrohard/LoRaHAM_Voice` `143b83f` — one checkout, two builds |
| Build | `gcc … loraham_voice_v107.c` with GTK 3, codec2, ALSA and ncurses → `loraham_voice`; the same source with `-DNO_GTK` → `loraham_voice_cli` (codec2, ALSA, ncurses — no GTK/X11 linkage) |
| Run | through a symlink in `<runtime>/config/files/` — the app reads its config from its binary's directory. GTK: started and stopped by lhpc (`DISPLAY`); terminal: the command lhpc prints, in a real TTY |
| Config | `<runtime>/config/files/loraham_voice.conf` (`KEY=VALUE`), shared by both variants and regenerated by every stack start; the in-app config dialog saves back to it |
| Resources | `audio.default` exclusive — claimed by both variants |
| Depends on | `loraham-daemon`, `requires_daemon_tx = DIRECT` |
| Install channel | source only. `libcodec2-dev`, `libasound2-dev` and `libncurses-dev` are in the default bootstrap; `libgtk-3-dev` only with `sudo bash bootstrap-deps.sh --spi-mode <mode> --with-gui` |

## Settings

|---|---|---|---|
| `callsign` | inherits the global operator base callsign while empty | | max 11 characters; `/` and `-` allowed (portable forms such as `N0CALL/P` — use your own call); with neither a local nor a global callsign the start is refused |

One file holds both bands (`lora433_*` / `lora868_*`); `active_band` is written from the band the
stack is started on. The daemon-side radio parameters live in [daemon](daemon.md).

## Position (GPS)

None — voice has no position setting.

## Notes

- **Headless:** `lhpc install voice && lhpc build voice` works on a Lite image. The build's GUI
  preflight drops the GTK component where the toolkit is absent; the terminal variant is offered
  only where the GTK app cannot run here — toolkit or display missing (where the GTK app can run it owns the audio device and the terminal variant is not).
- The terminal variant is interactive like chat: `lhpc stack start voice` brings up the daemon,
  generates the config and prints the command (the Dashboard's Voice card shows the same); run it
  locally or over SSH. Space = PTT. Starting `loraham-voice-cli` on its own is refused — only a
  stack start generates the shared config.

## Conflicts

- Both variants claim `audio.default` exclusively, so they never run at once — the terminal
  variant is refused while the GTK app holds the device.
- One app stack per band — see [kiss](kiss.md).
