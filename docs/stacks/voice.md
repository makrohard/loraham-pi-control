# Stack: Voice

Codec2 voice over LoRa through the daemon on 433 or 868 MHz, in two builds of one source: a GTK
desktop app (`loraham-voice`, needs a display and an audio device) and an ncurses terminal variant
(`loraham-voice-cli`) for headless boxes. The daemon runs **DIRECT**: the app paces its own TX by
airtime, and a MANAGED CAD wait would gap live audio.

| | |
|---|---|
| Components | `loraham-voice` (main, `gui_optional`) · `loraham-voice-cli` (interactive terminal variant) |
| Source / pin | `src/LoRaHAM_Voice` ← `makrohard/LoRaHAM_Voice` — one checkout, two builds |
| Build | `gcc … loraham_voice_v107.c` with GTK 3, codec2, ALSA and ncurses → `loraham_voice`; the same source with `-DNO_GTK` → `loraham_voice_cli` (no GTK/X11 linkage) |
| Run | via a symlink in `<runtime>/config/files/` (the app reads its config beside its binary). GTK: started and stopped by lhpc (`DISPLAY`); terminal: run the command lhpc prints in a real TTY |
| Config | `<runtime>/config/files/loraham_voice.conf` (`KEY=VALUE`), shared by both variants, regenerated by every stack start; the in-app config dialog saves back to it |
| Resources | `audio.default` exclusive — claimed by both variants |
| Depends on | `loraham-daemon`, `requires_daemon_tx = DIRECT` |
| Install channel | source only. `libcodec2-dev`, `libasound2-dev` and `libncurses-dev` are in the default bootstrap; `libgtk-3-dev` only with `--with-gui` ([cli](../cli.md#deps)) |

## Settings

| param | 433 | 868 | notes |
|---|---|---|---|
| `callsign` | inherits the global operator base callsign while empty | | max 11 characters; `/` and `-` allowed (portable forms such as `N0CALL/P` — use your own call); with neither a local nor a global callsign the start is refused |
| `freq` | `434.700` | `869.525` | MHz |
| `sf` | 7 | 7 | a voice packet must spend less time on the air than the audio it carries, or the app marks the mode `[VERBOTEN!]` and will not transmit; at 869.525/BW250 that rules out SF8 and slower (SF11 needs ~1.2 s for 260 ms of audio) |
| `bw` | 125.0 | 250.0 | kHz |
| `cr` | 5 | 5 | 4/CR |
| `crc` | 1 | 1 | |
| `preamble` | 8 | 16 | |
| `sync` | `0x12` | `0x2B` | |
| `power` | 17 | 10 | dBm |
| `ldro` | 2 | 2 | 0 = off, 1 = on, 2 = auto |
| `codec_mode` | 0 | | Codec2 mode index 0–7 |
| `audio_capture` / `audio_playback` | `default` | | ALSA devices. The terminal client lists up to 16 PCMs (capture-capable or without IOID restriction): with two or more it uses the saved names if both are listed, else asks at start (Enter = default); with one it uses it; with none it keeps the saved names |

One file holds both bands (`lora433_*` / `lora868_*`); `active_band` is written from the band the
stack is started on. Daemon-side radio parameters: [daemon](daemon.md#radio-parameters).

## Position (GPS)

None — voice has no position setting.

## Notes

- **Headless:** `lhpc install voice && lhpc build voice` works on a Lite image. The build drops
  the GTK component where the toolkit is absent; the terminal variant is offered only where the
  GTK app cannot run (toolkit or display missing).
- Terminal variant: Space = PTT. Starting `loraham-voice-cli` on its own is refused — only a
  stack start generates the shared config.

## Conflicts

- Both variants claim `audio.default` exclusively, so they never run at once.
- One app stack per band — see [kiss](kiss.md#notes).
